💡 Principe : vous avez un projet de référence ecole-app qui fonctionne. Pour chaque nouveau client, vous en faites une copie, vous configurez une nouvelle base Neon et un nouveau projet Vercel, puis vous déployez.

🚀 Procédure complète pour un nouveau client

1

Copier le dossier

Sur votre bureau, vous avez ecole-app (votre projet de référence). Créez une copie pour le nouveau client :

cd "C:\Users\Sahnoun HAWALA\Desktop"
robocopy "ecole-app" "ecole-client-b" /E /XD node_modules .next .git

💡 Pourquoi robocopy et pas Copy-Item ?

robocopy est beaucoup plus rapide et exclut les dossiers lourds (node_modules, .next, .git) grâce à l'option /XD.

Si vous préférez Copy-Item, faites-le mais supprimez manuellement node_modules, .next et .git après.

2

Nettoyer le dossier copié

Supprimez les fichiers liés à l'ancien client :

cd "C:\Users\Sahnoun HAWALA\Desktop\ecole-client-b"
Remove-Item ".env" -Force -ErrorAction SilentlyContinue
Remove-Item ".env.local" -Force -ErrorAction SilentlyContinue
Remove-Item ".vercel" -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item ".next" -Recurse -Force -ErrorAction SilentlyContinue

🗑️ Pourquoi supprimer ces fichiers ?

  • .env : contient les secrets de l'ancien client (à remplacer)
  • .vercel : lie le dossier au projet Vercel de l'ancien client
  • .next : cache de build (à regénérer)
3

Installer les dépendances

npm install

Cette commande va :

  • Installer toutes les dépendances (next, react, prisma, bcryptjs, jose, jspdf, tailwindcss...)
  • Exécuter postinstall → prisma generate
  • Prendre ~2-3 minutes
✅ Résultat attendu : added XXX packages in XXs et ✔ Generated Prisma Client
4

Créer le projet Neon

Rendez-vous sur console.neon.tech et connectez-vous.

  1. Cliquez sur "New Project"
  2. Nommez-le (ex: ecole-client-b)
  3. Région : Frankfurt
  4. Cliquez sur Create
  5. Cliquez sur "Connect" → copiez la connection string (mode Pooled)

🗄️ D'où vient cette URL ?

Générée par Neon au moment de la création du projet. C'est l'adresse unique de la base de données du client.

Format : postgresql://neondb_owner:motdepasse@ep-xxx-pooler.region.aws.neon.tech/neondb?sslmode=require

⚠️ Gardez cette URL précieusement. Elle deviendra la valeur de DATABASE_URL.
5

Générer une nouvelle CONFIG_ENCRYPTION_KEY

Cette clé doit être UNIQUE pour chaque client. Ne réutilisez jamais celle d'un autre client.

node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

Copiez la sortie (ex : xY3kL9...==).

🔐 Pourquoi une clé unique ?

Cette clé est la clé maîtresse qui chiffre toute la configuration en base (AES-256-GCM). Si elle fuit, toutes les données chiffrées de ce client sont compromises. Utiliser la même clé pour tous les clients = une fuite = tous les clients compromis.

⚠️ Ne perdez jamais cette clé. Sans elle, la config chiffrée du client est irrécupérable.
6

Créer le fichier .env

cd "C:\Users\Sahnoun HAWALA\Desktop\ecole-client-b"
notepad .env

Collez ce contenu en remplaçant les valeurs :

CONFIG_ENCRYPTION_KEY="COLLER_LA_CLE_GENEREE"
NEXT_PUBLIC_APP_URL="http://localhost:3000"
DATABASE_URL="COLLER_URL_NEON_ICI"
BOOTSTRAP_DATABASE_URL="COLLER_URL_NEON_ICI"
BOOTSTRAP_ADMIN_EMAIL="admin@ecole-client-b.tn"
BOOTSTRAP_ADMIN_PASSWORD="Admin123!"

Sauvegardez et fermez.

7

Appliquer les migrations Prisma

npx prisma migrate deploy
⚠️ Utilisez migrate deploy, PAS migrate dev. migrate dev créerait une nouvelle migration (ce qui n'est pas nécessaire pour un nouveau client).

Résultat attendu :

Applying migration `xxx_init`
All migrations have been successfully applied.
💡 Si erreur P1001: Can't reach database server → Neon est en pause. Allez sur console.neon.tech → SQL Editor → SELECT 1; pour le réveiller, puis relancez.
8

Bootstrap (config chiffrée + admin)

npm run bootstrap

Résultat attendu :

🚀 Bootstrap de la configuration...
✅ Configuration chiffrée écrite en base
✅ Admin créé : admin@ecole-client-b.tn / Admin123!
9

(Optionnel) Seed de données de test

npx prisma db seed
⚠️ Ne lancez PAS cette commande pour un vrai client. Elle insère des données de test (prof@ecole.tn, eleve1@ecole.tn, etc.) que vous ne voulez pas en production.
10

Lancer le serveur en local (test)

$env:NODE_OPTIONS="--max-old-space-size=4096"
npm run dev

Ouvrez http://localhost:3000 → login admin → /admin/configuration → personnaliser (logo, nom, année).

✅ Si tout fonctionne en local, on peut passer au déploiement.
11

Créer le projet Vercel

vercel login
vercel link

Répondez :

  • Set up and deploy? → y
  • Which scope? → elec-connect
  • Link to existing project? → n
  • Project's name? → ecole-client-b
  • Directory? → ./
12

Configurer les variables sur Vercel

vercel env add DATABASE_URL production --value "COLLER_URL_NEON" --sensitive --yes
vercel env add CONFIG_ENCRYPTION_KEY production --value "COLLER_CLE_GENEREE" --sensitive --yes
vercel env add NEXT_PUBLIC_APP_URL production --value "https://ecole-client-b.vercel.app" --yes
vercel env add CRON_SECRET production --value "COLLER_CRON_SECRET" --sensitive --yes

🔑 D'où viennent ces valeurs ?

  • DATABASE_URL → depuis console.neon.tech
  • CONFIG_ENCRYPTION_KEY → générée à l'étape 5
  • NEXT_PUBLIC_APP_URL → l'URL Vercel du projet (visible dans Overview après le 1er déploiement)
  • CRON_SECRET → généré dans /admin/configuration (étape 14). Pour l'instant, mettez une valeur temporaire.
13

Déployer en production

vercel deploy --prod

Résultat attendu :

✅ Production: https://ecole-client-b.vercel.app
⏰

Configurer le CRON_SECRET

  1. Ouvrez https://ecole-client-b.vercel.app
  2. Connectez-vous avec admin@ecole-client-b.tn / Admin123!
  3. Allez sur /admin/configuration
  4. Section ⏰ Tâches automatiques (Cron)
  5. Cliquer 🎲 Générer un secret aléatoire
  6. Cliquer 📋 Copier
  7. Cliquer Enregistrer la configuration
  8. Retourner sur Vercel → Settings → Environment Variables → mettre à jour CRON_SECRET
  9. Redeploy
⚠️ Le secret doit être identique dans l'application et dans Vercel. Sinon, le cron retourne 401.
15

Personnaliser le client

Dans l'application, allez dans :

  • /admin/configuration → logo, nom de l'école, année scolaire
  • /admin/classes → créer les classes
  • /admin/matieres → créer les matières
  • /admin/salles → créer les salles
  • /admin/utilisateurs → créer les profs, élèves, parents
  • /admin/volume-horaire → configurer les volumes horaires
  • /admin/emplois/generer → générer l'emploi du temps
🎉 Le client est prêt à être utilisé !

⚠️ Points de vigilance

Sujet Détail
robocopy vs Copy-Item robocopy est beaucoup plus rapide et exclut les dossiers lourds
CONFIG_ENCRYPTION_KEY unique Ne réutilisez JAMAIS la clé d'un autre client. Une clé par client
migrate deploy Pas migrate dev — sinon ça crée une nouvelle migration
Neon en pause Réveillez avec SELECT 1; dans SQL Editor
.env propre Le .env de l'école A ne doit jamais être copié
.vercel supprimé Sinon, le déploiement irait sur le projet Vercel de l'école A
Ne pas lancer le seed Pour un vrai client, ne lancez pas prisma db seed (données de test)
